    Debug tools¶

    /GASPALS/Systems/DebugTools/AC_DebugTools is a component on SandboxCharacter_Mover that groups the sandbox's demo and debug tools: shooting characters into ragdoll, spawning or rotating characters, teleporting and flying. It works on any pawn that implements BPI_RagdollSystem (itself or on its ragdoll component) and TeleportCharacter from BPI_SandboxCharacter_Pawn (both sample pawns do; fly needs a Mover pawn), in any game mode; RagdollLevel, with its placed target characters and physics obstacles, is the place to try it. Enable Debug Tools turns it off, and it can be removed from the pawn (Turning systems on and off).

    Controls¶

    Input Condition Action
    Left Button aim held (Right Button) Shoot: the character hit goes ragdoll, with an impulse at the bone that was hit. Without aim, Left Button is a takedown.
    E aim held Spawn or rotate: rotate the character you aim at by 90 degrees, or spawn a new character on the floor where you aim. Without aim, E is a shove or a bench interaction.
    J Teleport to the point under the view.
    Z keyboard only Fly: toggle the Mover Flying mode.

    N (next pawn) and M (next character) belong to the player controller, not to this component. See Controls.

    How it works¶

    • Shoot. The component takes the view from the pawn's camera. The server traces along it for physics bodies; the character hit is asked to ragdoll and to push the bone that was hit (BPI_RagdollSystem, through Get Ragdoll System). A Mover character applies the impulse once its body is simulating. The CMC character's mesh has no collision, so the shot doesn't hit it.
    • Spawn or rotate. The server traces along the view. A character hit (Mover or CMC) is turned 90 degrees; anything else spawns a new character of the same class at the hit point (or at the end of the trace), facing you. Only the last Max Spawned Characters spawned characters are kept: the oldest is destroyed.
    • Teleport. The player controller (PC_Sandbox) asks the pawn's debug tools to teleport it. A sphere trace runs from the eyes along the view; the pawn moves just off the surface hit, or to the end of the trace. Pawns without the component (the CMC pawn) use the controller's own teleport, with the controller's Teleport Max Distance.
    • Fly. Switches the Mover pawn between the Flying mode and falling, with an on-screen message.

    Configuration¶

    Settings on the AC_DebugTools component of the Mover pawn:

    Setting Category Default Use
    Enable Debug Tools Debug Tools > General true Master switch for the shot, spawn / rotate, teleport and fly tools of this component.
    Shot Trace Distance Debug Tools > Demo 100000 Length of the shot trace in cm.
    Shot Impulse Debug Tools > Demo 2500 Impulse applied to the bone hit by a shot.
    Spawn Trace Distance Debug Tools > Demo 1000 Reach of the spawn / rotate trace in cm; with no hit the character spawns at the end of the trace.
    Max Spawned Characters Debug Tools > Demo 3 Spawned characters kept alive; the oldest is destroyed beyond this.
    Teleport Max Distance Debug Tools > Teleport 10000 Reach of the teleport trace in cm.

    Shipping a game

    Turn Enable Debug Tools off on your pawn, or remove the component, so players can't spawn characters or teleport. The component is optional: nothing else in GASPALS depends on it.

    The full variable and function list is in the Pawns and Anim Blueprints reference.

    Networking¶

    Tool How it replicates
    Shoot The owner sends its view to the server (reliable server RPC); the server traces and starts the ragdoll, and the impulse is multicast to every machine.
    Spawn or rotate The owner sends its view to the server (reliable server RPC). Spawned characters replicate as actors. Rotating another player's pawn is done by that player's machine (a replicated counter tells it to turn), so its own prediction doesn't undo it.
    Teleport, fly Run locally on the owner, so they work in standalone and for the listen server host. A client's teleport or fly is overridden by the server: both are single-player debug helpers.

    In a listen server test, expect one correction when the host shoots or rotates a client's pawn.

    Limitations¶

    • Shoot needs the characters hit to have a ragdoll system (BPI_RagdollSystem); rotate and teleport need TeleportCharacter (BPI_SandboxCharacter_Pawn); fly needs a CharacterMoverComponent on the owner.
    • The demo shot is a debug tool, not a weapon system: no damage, ammunition or effects.
    • The movement debug shapes (DDCvar.DrawCharacterDebugShapes) are drawn by the Mover pawn itself, not by this component.
