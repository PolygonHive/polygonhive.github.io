    Ragdoll and interactions¶

    GASPALS has two ragdoll implementations, one per pawn type:

    CMC pawn Mover pawn
    Pawn SandboxCharacter_CMC SandboxCharacter_Mover
    Implementation AC_RagdollSystem component A Mover movement mode (BP_MovementMode_Ragdoll) plus a Physics Control component
    Input X toggles ragdoll X ragdolls, Space gets up
    Entry Keeps the movement momentum (Inherited Velocity Scale); the legs collide with each other The Ragdoll physics profile; the legs collide with each other
    Get-up Get-up animation chosen from the pose (front, back) and the held item Get-up animations chosen from the pose (front, back, roll)
    Physical animation No Off by default (kinematic); DDCVar.CharacterPhysics.DefaultProfile 1 turns it on
    Interactions No Takedowns and shoves between characters; demo shooting and spawning (debug tools)
    Level Any (DefaultLevel starts on the CMC pawn) Any (N to the Mover pawn in DefaultLevel); RagdollLevel has targets and obstacles

    CMC ragdoll (AC_RagdollSystem)¶

    /GASPALS/Systems/RagdollSystem/AC_RagdollSystem. Press X (IA_Ragdoll) to toggle.

    Start: the owner calls StartRagdoll, which asks the server (Server_StartRagdoll) to multicast it to everyone. Each machine stops montages, turns the capsule's collision off, switches the mesh to physics (Ragdoll profile, simulating the bodies below the pelvis), applies the entry physics (ApplyEntryPhysics, below), and sets the movement mode to none. OnRagdollStarted fires.

    Entry physics: right after the bodies start simulating, and before the movement mode is cleared, the bodies get the pawn's velocity times Inherited Velocity Scale, so a running character keeps its momentum instead of dropping in place, and collision is turned on between the left and right leg bodies so the legs don't pass through each other (the Mover ragdoll profile does the same for the legs). Settings on AC_RagdollSystem (Ragdoll > Entry), set per pawn because the bone names depend on the skeleton:

    Setting Default Use
    Inherited Velocity Scale 1.0 Share of the movement velocity the ragdoll starts with. 1 keeps the momentum, 0 drops in place (the behavior before this setting).
    Left Leg Bones thigh_l, calf_l, foot_l Bodies of the left leg.
    Right Leg Bones thigh_r, calf_r, foot_r Bodies of the right leg; each collides with each left leg body.

    Stop: StopRagdoll reverses it the same way and fires OnRagdollEnded. Each machine turns physics off and puts the mesh back where it sat on the capsule when the ragdoll started (CacheMeshTransform / RestoreMeshTransform: the simulated pelvis drags the mesh away during the ragdoll). The capsule and mesh get back the collision settings they had when the ragdoll started (cached by CacheCollisionState), so a pawn with its own collision setup keeps it. On the ground the pawn walks again and plays a get-up montage picked from the pose (lying on the back or the front) and the held item (Get Up Back / Front settings: Default, right hand, left hand, two hands); in the air it falls with the body's last velocity.

    While ragdolling the CMC accepts the client's position (client-authoritative flags), so the capsule follows the body without corrections. The component then tells the pawn's other components through BPI_RagdollSystemListener; the camera system uses it to switch to the ragdoll perspective (see Camera). Enable Ragdoll (General) turns the system off, and the component can be removed from the pawn (Turning systems on and off).

    Settings and functions: Ragdoll reference.

    Mover ragdoll¶

    SandboxCharacter_Mover is the player pawn of RagdollLevel (game mode GM_Sandbox_Ragdoll), and it is the Mover pawn of every other level too: the ragdoll, takedowns and debug tools work wherever it plays. It has:

    • a Physics Control component: when not ragdolling, DDCVar.CharacterPhysics.DefaultProfile picks kinematic (0, default: the body plays the animation exactly) or physical animation (1: every limb is a simulated body pulled toward the animation, so it reacts to contacts, but hands and arms can catch on walls, for example in cover). An AC_PostABPTick helper updates the strengths from animation curves right after the Anim Blueprint runs.
    • the Ragdoll movement mode and the BP_MovementTransition_SuggestedMode transition;
    • interactions with other characters (takedowns, shoves);
    • the debug tools component (AC_DebugTools): demo shot, spawn or rotate characters, teleport, fly.

    Entering and leaving ragdoll¶

    1. X (IA_Ragdoll) sets an injury state and, on the owner, writes a ragdoll request into the Mover input. The suggested-mode transition switches to the Ragdoll mode inside the simulation, so the owner and the server agree. (A server forcing a remote player into ragdoll queues the mode directly.)
    2. Every machine applies the ragdoll look when the mode changes: physics on, the Ragdoll physics profile.
    3. While ragdolling, the owner can roll the body with the move input; the roll travels in the input too. Remote ragdolls are pulled toward the replicated capsule so they stay in sync.
    4. Space on the ground leaves the ragdoll. Entering and leaving ragdoll put the capsule back on the collision profile the pawn was built with (GetDefaultCapsuleProfile, CharacterCapsule in the sample), which also clears a takedown's collision override. The owner picks a get-up montage from the body's pose (lying on the back or the front, rolling) and sends it in the input; the server and the owner play it.

    Settling¶

    The ragdoll's arms are pulled toward the animated pose, which keeps moving while the body lies still, so the hands would keep shaking. Once the body has stayed slower than Ragdoll Settle Speed for Ragdoll Settle Delay, the physics control strengths fade to zero over Ragdoll Settle Blend Time; when the body moves again (pushed, shot, rolled) they come back four times faster. In a test, the hand of a settled ragdoll moved about 16 times less per frame (0.33 to 0.02 cm) and drifted 0.25 cm instead of 8 cm over three seconds.

    Settings on SandboxCharacter_Mover (GASPALS > Ragdoll > Settle):

    Setting Default Use
    Ragdoll Settle Speed 15 Body speed (cm/s) below which the ragdoll counts as still.
    Ragdoll Settle Delay 0.3 Seconds below that speed before the strengths start fading.
    Ragdoll Settle Blend Time 0.5 Seconds to fade the strengths to zero (coming back takes a quarter of it).

    Takedowns and shoves¶

    Near another character:

    Input Action
    Left Button Takedown: a paired takedown animation on both characters.
    E Shove.

    The interaction is matched with multi-character motion matching (MMI): the best paired animation for both characters' poses and positions is chosen, and both are warped into place. On a client, the initiator plays its part at once and asks the server (Server_TryCharacterInteraction), which checks the victim (walking, not already in a root-motion animation, within 3.5 m) and multicasts the interaction. Each machine sets up the participants (ignored collisions, tick order, the animation contexts the Anim Blueprint uses for constraints).

    Demo tools¶

    The AC_DebugTools component on the Mover pawn. Hold aim (Right Button), then:

    Input Action
    Left Button Shoot: the character hit goes ragdoll with an impulse.
    E Spawn a character where you aim, or rotate the one you aim at.

    Clients send these to the server with the view; the server traces, applies the ragdoll and multicasts the impulse. Settings (trace distances, impulse, spawn limit, an on/off switch) and the teleport and fly keys are on the Debug tools page.

    Physics obstacles¶

    RagdollLevel has moving obstacles (bumpers, hammers, turnstiles, moving platforms) on the Obstacle collision channel, which the Ragdoll profile blocks. Walk into them with physical animation on, or ragdoll into them.

    The locally controlled Mover pawn sweeps a sphere from the neck to between the feet every frame; an obstacle hit knocks it into ragdoll. Settings on SandboxCharacter_Mover (GASPALS > Ragdoll > Obstacles):

    Setting Default Use
    Ragdoll On Obstacle Hit true Off: obstacles only push the capsule.
    Ragdoll Obstacle Object Types Obstacle Object types that knock the pawn over.
    Ragdoll Obstacle Trace Radius 15 Radius of the sweep in cm.

    Networking summary¶

    Event CMC pawn Mover pawn
    Start / stop Server RPC, then reliable multicast Mover input request and transition; cosmetics on mode change
    Roll n/a Mover input
    Get-up Played on every machine by the stop multicast Montage chosen by the owner, sent in the input, played on server and owner
    Interactions n/a Client predicts, server validates, reliable multicast

    In a listen server test, expect one correction for each of: a takedown or shove from the host on a client, a shot from the host, the host rotating a client. Ragdoll bodies agree within a few centimeters across machines.

    Limitations¶

    • The two implementations are separate: the CMC pawn has no physical animation, settling or interactions.
    • Takedowns and shoves are on the Mover pawn only, between Mover characters.
    • The CMC ragdoll simulates the bodies below the pelvis, with no physical animation and no roll.
