    Troubleshooting¶

    Start with the basics: are the project settings copied, and does the problem happen in the template's DefaultLevel? If it works there, compare your level, pawn or character with the sample.

    Setup¶

    Symptom Cause Fix
    The camera is a plain spring arm; no shoulder, crouch or cover offsets DDCVar.NewGameplayCameraSystem.Enable missing or false Copy the data-driven console variables. Restart Play after changing it.
    An orange message lists missing console variables at play start The project does not declare those DDCvar.* data-driven console variables; the systems fall back to defaults (no visual override, the game mode's default pawn) Copy the console variables from Installation.
    Characters never change with M The level's game mode is not GM_Sandbox or a child Use GM_Sandbox or derive from it.
    Errors about missing gameplay tags, no foley sounds DefaultGameplayTags.ini not copied Copy it.
    Packaging fails with exit code 25 The project enables the Game Features plugin but scans no GameFeatureData asset type Add the entry from Installation.
    "Failed to load class /Script/GameFeatures.GameFeatureData" on every editor start A GameFeatureData scan entry without the Game Features plugin Remove the entry from Config/DefaultGame.ini, or enable Game Features if you use it.
    Packaging asks for a compiler The plugins GASPALS uses are not on by default Install Visual Studio 2022 with the game development workload.
    The packaged game closes at start; its log says "Unable to load plugin 'GASPALS'" and names a missing dependency GASPALS isn't enabled in the project's .uproject, so the package uses the stock game executable without GASPALS's engine plugins Enable GASPALS in the project (see Installation) and package again.
    Traversal, cover or the obstacle course stop working after merging the collision settings Your project has its own custom channels, so the channel positions the Blueprints store changed Pick the channels again by name: Traversable Trace Channel, Cover Trace Channel, Ragdoll Obstacle Object Types (see Project settings).
    The player has no controls; InputMappingContexts is empty on this pawn The pawn's Input Mapping Contexts map is empty Add IMC_Sandbox (or your context) in the pawn's class defaults.

    Locomotion and traversal¶

    Symptom Cause Fix
    Pressing jump at an obstacle only jumps It does not block the Traversable channel, Traversable Trace Channel points at another channel, or it is too narrow See Make objects traversable; check the setting on the pawn's AC_TraversalLogic.
    No slide The CMC pawn has none; on the Mover pawn, slides need sprint speed (over 380) and wait for the 0.75 s cooldown Sprint, then crouch.
    The character keeps strafing The CMC pawn starts with strafe on Toggle strafe (middle mouse), or change CharacterInputState > Wants To Strafe on the pawn.
    The Mover pawn suddenly flies Z is the Mover debug flying toggle Press Z again, or turn off Enable Debug Tools on the Mover pawn's AC_DebugTools component.
    Feet slide or float on a new character Retargeting Check the IK Retargeter's chains and retarget pose.

    Cover¶

    Symptom Cause Fix
    No cover at all on your pawn Enable Cover was turned off on its component (it is on by default) Turn it on in the pawn's cover component.
    Cover never triggers on some walls The wall ignores the Cover channel Use a preset that blocks Visibility (they all block Cover), or set its Cover response to Block.
    Characters take cover on foliage or fences Those objects block Cover Set their Cover response to Ignore (Build a cover level).
    The cover button does nothing Enable Sticky Cover off, nothing within Sticky Cover Reach, or first person with First Person Sticky Cover = Disabled Check the settings and the cover marker (it shows on valid cover).
    Cover run goes straight into obstacles No navmesh Add a NavMeshBoundsVolume and build paths.
    Cover run fails on clients only Client-side navigation is off bAllowClientSideNavigation=True (project settings).
    Mover and CMC behave differently in cover Their cover components are tuned separately Compare the component settings; the cover reference shows where the samples differ.

    Equipment and overlays¶

    Symptom Cause Fix
    The item floats near the feet The attach socket is missing on the skeleton Add the overlay_* sockets to the character's Skeleton.
    The support hand does not reach the item No HandIK socket (or the item's Hand IK Socket name), or the pose's enable_handik_* curve is 0 Add the socket; set the curve in the pose's curve map.
    The item is not in the hands in first person Create First Person Copy is off in the item's data asset, or the pawn has no AC_FirstPersonSystem Turn Create First Person Copy on; keep AC_FirstPersonSystem on the pawn.
    Other players' arms snap when they aim up or down The overlay child's Aim Sweep Interp Speed Remote is 0 Set Remote to 10 on the child (keep Local at 0: interpolating the owner's arms makes the weapon lag and step).
    The Overlay Pose set on the pawn does not show An item is equipped at spawn; its pose wins Start with Selected Equipment Unequip, or pick the stance later.
    OverlayPoseLayers has no anim layer class for the selected OverlayPose (or OverlayBodyLayers) The enum value has no row in the map Add the row on AC_OverlaySystem (and on the pawn's component if it overrides the map).

    First person¶

    The pawn's AC_FirstPersonSystem prints setup problems on screen, in orange, for the local player, for 10 seconds. Each message starts with GASPALS First Person (<body name>):, where the body is the pawn or the visible character. The fields named below are in the body's first-person setup (PDA_FirstPersonSetup): Default Setup on the pawn's AC_FirstPersonSystem, or First Person Setup on a retargeted character.

    Message (abridged) Fix
    no first-person setup Set First Person Setup on your BP_RetargetedCharacter_Base child (duplicate DA_FirstPersonSetup_Manny), or implement BPI_FirstPersonCharacter (GetFirstPersonSetup) on your visual override. Until then the body mesh is reused in first person with the head hidden.
    no third-person Skeletal Mesh Component found On a character, implement BPI_VisualOverride (GetVisualBodyMesh) to return the body mesh; on a pawn, set Third Person Mesh Name on AC_FirstPersonSystem to the body component's name.
    no first-person mesh was generated Fill Full Meshes (or Arms Meshes and Body Meshes for FirstPersonOverlaySplit) in the body's setup.
    the first-person skeleton has no camera bone Add a virtual bone from root to head named VB Camera in the Skeleton editor, or set Camera Bone in the setup to your camera bone.
    the first-person skeleton has no head bone Set Head Bone in the setup to the skeleton's head bone.
    this skeleton is not the UEFN mannequin and its first-person setup has no Retargeter ... so TrueFirstPerson is used Set Retargeter in the setup to an IK Retargeter from the UEFN mannequin to this skeleton, or keep TrueFirstPerson for this character.
    FirstPersonOverlaySplit needs both ArmsMeshes and BodyMeshes Fill both Arms Meshes and Body Meshes in the setup.
    Symptom Cause Fix
    A character is in TrueFirstPerson although the pawn uses an overlay mode Its skeleton is not the UEFN mannequin and its setup has no Retargeter Set Retargeter in the character's first-person setup.
    The camera sees the inside of the head or the chest Eye offset Tune Eye Offset in the body's first-person setup ((0, 12, 0) for UE5 and MetaHuman heads).
    ADS sights do not line up Eye offset or the item's ADS socket Fix the eye offset first, then the socket.
    The rear sight is clipped Near clip plane NearClipPlane=1 in the project settings.
    The camera does not follow the body on a retargeted character CR_FirstPerson_BodyCamera not compiled after an edit Open and compile the Control Rig.

    Characters¶

    Symptom Cause Fix
    The character is a frame behind the pawn GetVisualBodyMesh does not return the body mesh, so it does not tick after the pawn mesh Override GetVisualBodyMesh in the character Blueprint to return its body component.
    The hands do not grip items on a retargeted character The hand IK curves do not reach the retargeted mesh Add a Curve Remap op (copy all source curves) to the IK Retargeter.
    MetaHuman clothing tears or stays in bind pose A follower with its own skeleton uses leader pose Leave its anim class empty and keep its post-process Anim Blueprint.

    Ragdoll¶

    Symptom Cause Fix
    The ragdoll won't get up The character only gets up once the body rests on a floor; a press in mid-air does nothing Press X or Space again after landing. On your own pawn, implement RequestGetUp from BPI_RagdollSystem (Ragdoll).

    Multiplayer¶

    Symptom Cause Fix
    A system works on the host but not for clients The component does not replicate Turn on Component Replicates on the pawn's component (see Networking).
    Remote Mover characters stutter Network Prediction settings missing Copy DefaultNetworkPrediction.ini.
    Remote CMC characters animate stiffly Acceleration not replicated p.EnableCharacterAccelerationReplication=1.
    Corrections during Mover play Something changed movement outside the input command Route movement changes through ProduceInput and transitions; np.PrintReconciles 1 lists corrections.
